# Changes in 1.1.0

[日本語（正本）](1.1.0.ja.md) | English

1.1.0 adds a build-time correction for `in` operators inside `for` initializers. It handles generated code that is valid ES3 but causes a syntax error in After Effects ExtendScript. The new correction and public diagnostic are a minor-version addition under the [v1 compatibility policy](../public-contract.md#changes-after-v1).

## Changes

- `protectCompatibility()` and Rollup's `extendscriptCompat()` turn affected initializers into preceding statements in the same scope. Detection includes `in` inside nested function bodies and covers array-copy helpers moved into initializers by Terser.
- The correction preserves labeled `break` and `continue`, evaluation order and count, and bindings for `this`, `arguments`, and direct `eval`. Expression initializers are parenthesized so anonymous function expressions and object expressions remain valid statements.
- `findCompatibilityIssues()` reports the original initializer with `code: "EC-20"` and `kind: "for-initializer-in"`. Automatically corrected EC-20 issues are not returned in `protectCompatibility().diagnostics`.
- In Rollup, correction always runs regardless of `diagnostics`; the build stops if an affected initializer remains afterward. Existing corrections and source-map updates are preserved.

## Updating consumers

Update the dependency to 1.1.0 and rebuild generated JSX. Place `extendscriptCompat()` after minification and include expansion, but before JSXBin conversion. Minifying corrected output again can undo the protection.

Existing entry points and option formats are retained, and the shipped runtime JavaScript is unchanged from 1.0.0. See [build-time compatibility](../build-compatibility.md#the-in-operator-in-for-initializers-ec-20) for correction conditions and restrictions on affected non-ES3 `let` and `const` declarations.

## Validation scope

The correction was merged in [PR #47](https://github.com/YukiWorks432/extendscript-compat/pull/47). In AE 26.5x89 / ExtendScript 4.5.6, all 15 cases that caused syntax errors before correction returned their expected results after correction. The corrected original `RectangleDirectionalMask.jsx` also passed whole-file syntax parsing; that check did not execute its layer operations. See the [host results and fixture/output hashes](https://github.com/YukiWorks432/extendscript-compat/blob/c72af07c8e78ac067b1ee9b314c6db64bf6722a0/docs/evidence/for-initializer-ae-26.5.json).

This version update changes only the version and distribution documentation relative to the corrected implementation. Existing host evidence is retained without repeating host tests or performance measurements. Host validation for this rule is limited to the stated Windows AE version; it does not establish support in other Adobe products, older versions, or macOS.
