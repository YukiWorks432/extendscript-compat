# 1.2.0の変更点

[English](1.2.0.md) | 日本語（正本）

1.2.0では、ホストアプリケーションの組み込みを変更しないponyfillモードをRollupへ追加しました。ES5を含む対応APIの補完を、通常のJavaScriptを書いたままバンドル内の実装へ切り替えられます。既存の`/runtime`と既定の設定を維持する機能追加として、[v1の互換性方針](../public-contract.ja.md#1x以降の変更)に沿ってマイナー番号を更新します。

## 更新内容

- `extendscriptCompat({ runtime: "ponyfill" })`で、対応する標準APIの呼び出し・参照をバンドル内の実装へ変換します。同じバンドルの`extendscript-compat/runtime`読み込みは空にし、ホストへpolyfillを導入しません。動的参照や外部JSXなどの制限は[ponyfillモード](../build-compatibility.ja.md#ponyfillモード)を参照してください。
- 変換を出力側へ移し、Rollupが生成する名前空間・再公開処理の`Object.keys`や`forEach`にも補完を適用します。複数チャンク間の関数参照と利用側の束縛を維持し、内部の補完実装は再変換しません。
- `Object.freeze`がない場合は、引数をそのまま返す限定的な代替処理を用います。`/runtime`では不足時に導入し、ponyfillとRollupの最終出力の直接呼び出し補正ではホストを変更しません。凍結・書き換え禁止を保証せず、既存の関数を維持します。
- `Object.create`・`Object.defineProperty`・`Object.getOwnPropertyDescriptor`を、`/runtime`とponyfillの両方へ限定補完として追加します。既存の関数を優先します。createは実際のnullプロトタイプを要求し、作れなければTypeErrorにします。definePropertyの代替処理は値の代入を優先し、属性指定を反映せずgetter・setterを拒否します。記述子の取得は通常の自身のデータに限定し、書き換え・削除属性を近似します。詳細は[Objectの限定補完](../../runtime/README.ja.md#objectの限定補完)を参照してください。
- ponyfillの初回実行で`String.prototype.this`が追加される不具合と、`substr`のネイティブ参照を修正しました。

## 導入と切り替え

依存関係を1.2.0へ更新し、生成済みJSXを再ビルドしてください。新規導入でホストを変更せずに使う場合は、ES3への構文変換・圧縮・include展開後、JSXBin化の前に次のプラグインを配置します。

```js
import { extendscriptCompat } from "extendscript-compat/rollup";

// Rollupのplugins内
extendscriptCompat({ runtime: "ponyfill" });
```

既に`/runtime`を読み込んでいる場合も、この設定で同じバンドル内の読み込みを抑止できます。設定を省略した場合は従来どおりpolyfillを導入します。別のスクリプトが既に導入したpolyfillを削除する機能はありません。

include展開は、先行するモジュール処理か、補完を参照できるスコープ内の先行するrenderChunkで済ませてください。遅い展開やIIFE外へ追加された未変換の補完対象はエラーにします。補正後に再圧縮すると保護を失う場合があります。

Rollupの外部名前空間でgetterが必要になるコードは、getterを使えないAEではエラーになります。外部値を固定してよい用途に限り、利用者が`output.externalLiveBindings: false`を明示できます。ライブラリはこの設定や`output.freeze: false`を強制しません。

## 検証範囲

実装は[PR #49](https://github.com/YukiWorks432/extendscript-compat/pull/49)から[#53](https://github.com/YukiWorks432/extendscript-compat/pull/53)で統合しました。最終実装の回帰テスト388件、配布物の導入・実行・型検査と、Ubuntu・Windows × Node.js 22・24のCIが成功しています。

AE 26.5x89 / ExtendScript 4.5.6では、`-m`で起動した4つの別プロセスで、3つのObject APIが未導入の状態から試験しました。ponyfill通常版・圧縮版は各794項目が成功し、ホストの組み込みに差分はありませんでした。polyfill通常版・圧縮版は各31項目が成功し、導入と再読み込み後の関数参照の保持を確認しました。実行環境識別子と成果物のSHA-256は、[PR #53](https://github.com/YukiWorks432/extendscript-compat/pull/53)本文の「AE実機試験の証跡」を参照してください。

今回の版番号・配布文書の更新では、実装コードを変更しません。検証用JSXのハッシュを照合して既存の実機証跡を維持し、実機試験や性能測定は繰り返しません。確認済みの実機環境は上記Windows版AEに限り、ほかのAdobe製品、旧版、macOSでの動作確認を示すものではありません。
