# 1.1.0の変更点

[English](1.1.0.md) | 日本語（正本）

1.1.0では、`for`の初期化部分にある`in`演算子をビルド時に補正します。標準ES3として有効でも、After EffectsのExtendScriptでは構文エラーになる生成物を扱えるようになります。補正規則と公開診断の追加として、[v1の互換性方針](../public-contract.ja.md#1x以降の変更)に沿ってマイナー番号を更新します。

## 更新内容

- `protectCompatibility()`とRollupの`extendscriptCompat()`が、対象の初期化部分を同じスコープの直前の文へ変えます。初期化部分の関数内にある`in`も検出し、Terserが配列複製用の関数を初期化部分へ移した場合にも対応します。
- ラベル付きの`break`・`continue`、評価順序と回数、`this`・`arguments`・直接の`eval`の束縛を保ちます。式の初期化は括弧で囲み、匿名関数式やオブジェクト式が文へ変わっても正しく解析できるようにします。
- `findCompatibilityIssues()`は、元の初期化部分を`code: "EC-20"`、`kind: "for-initializer-in"`として返します。自動補正したEC-20は`protectCompatibility().diagnostics`へ通知しません。
- Rollupでは、`diagnostics`設定にかかわらず補正し、対象の構造が補正後にも残っていればビルドを停止します。既存補正とソースマップ更新も維持します。

## 利用時の確認

1.1.0へ依存関係を更新し、生成済みJSXを再ビルドしてください。Rollupでは圧縮・include展開後、JSXBin化の前に`extendscriptCompat()`を配置します。補正後の再圧縮は、補正を失わせる場合があります。

既存の公開入口と設定の形式を維持し、配布する実行時JavaScriptは1.0.0から変更していません。EC-20の条件と、ES3外の`let`・`const`宣言を対象にした場合の制限は、[ビルド時の互換補正](../build-compatibility.ja.md#for初期化部分のin演算子ec-20)を参照してください。

## 検証範囲

補正実装は[PR #47](https://github.com/YukiWorks432/extendscript-compat/pull/47)で統合しました。AE 26.5x89 / ExtendScript 4.5.6の実機では、補正前に構文エラーになる15例が、補正後はすべて期待結果と一致しました。元の`RectangleDirectionalMask.jsx`でも、補正後の全体の構文解析が成功しています。レイヤー操作そのものをこの確認で実行したわけではありません。[実機結果と資料・生成物のハッシュ](https://github.com/YukiWorks432/extendscript-compat/blob/c72af07c8e78ac067b1ee9b314c6db64bf6722a0/docs/evidence/for-initializer-ae-26.5.json)を参照してください。

この版の更新では、補正実装から版番号と配布文書だけを変更します。既存の実機証跡を引き継ぎ、実機試験や性能測定は繰り返しません。今回の規則の実機確認は上記のWindows版AEに限り、ほかのAdobe製品、旧版、macOSでの動作確認を示すものではありません。
