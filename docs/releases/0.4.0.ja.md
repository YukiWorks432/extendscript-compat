# 0.4.0の変更点

[English](0.4.0.md) | 日本語（正本）

0.4.0では、Rollupの`extendscriptCompat()`が互換補正後の出力をES3構文として自動検査します。従来は通っていたES3外の出力を拒否するため、0.x系列の入力条件の変更としてマイナー番号を更新します。公開APIや設定項目の追加はありません。

## 更新内容

- 各出力チャンクをAcornで検査し、不適合なら位置を含むエラーでビルドを停止します。予約語のプロパティも検査し、`object.for`や`{ default: 1 }`を拒否します。`object["for"]`や`{ "default": 1 }`は使用できます。
- 構文検査は`diagnostics: "off"`でも有効です。通知設定によって検査が無効になることはありません。
- 検査は互換補正とBOM付与の後に行います。引用符付きの予約語プロパティ、日本語、BOM、ソースマップを維持します。
- Acornを通常依存に含めます。利用側での直接導入や検査関数の呼び出しは不要です。`protectCompatibility()`など既存の補正APIを直接使う場合は、その呼び出しにES3構文検査を含みません。
- npm公開後の検証で、レジストリへの版情報の反映を最大5分待ちます。ハッシュの不一致や通信エラーを未反映として扱うことはありません。

## 移行時の確認

ES3構文への変換、圧縮、include展開を`extendscriptCompat()`より前に完了させてください。後続の処理による再圧縮は、補正と検査の保証から外れます。

Terserを使う場合は、最上位に`ie8: true`を指定してください。既定設定では`object["for"]`が`object.for`へ変わり、新しい検査で失敗することがあります。

```js
terser({ ie8: true });
```

プラグインはES3への変換器ではありません。ES2015以降の構文、TypeScript、ESモジュール構文、E4X、未展開のプリプロセッサー指示、関数外の`return`は受け入れません。詳細は[ビルド時の互換補正](../build-compatibility.ja.md)を参照してください。

## 検証範囲

検証は、Ubuntu・WindowsとNode.js 22・24の組み合わせ、公開入口と型定義、通常・圧縮時のRollup出力とソースマップ、不正な出力の拒否、梱包した配布物の導入を対象とします。

配布する実行時のJavaScriptは0.3.2から変更していません。今回の版ではAdobe実機の再検証を行っていません。構文検査は実行時APIの有無やAdobe製品での動作を保証するものではなく、既存の実機検証条件と未確認事項は[0.3.1の検証範囲](0.3.1.ja.md#検証範囲)を引き継ぎます。
