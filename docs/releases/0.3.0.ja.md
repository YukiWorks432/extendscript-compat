# 0.3.0の変更点

[English](0.3.0.md) | 日本語（正本）

0.3.0では実行時の互換補正を拡充し、Unicode文字と数値変換の補正を追加しました。ビルド時に標準で適用される処理が増えるため、0.2.0から更新する際は出力と警告を確認してください。

## 実行時の互換補正

`extendscript-compat/runtime`にJSONとES5・ES6の一部のポリフィルを追加しました。読み込みにより、同じExtendScriptエンジンを使う他のスクリプトにも影響します。`trim`は現在のECMAScriptで定義された空白を扱い、`Number.parseInt`は補正後の`parseInt`と同じ関数になります。ES5・ES6の全機能は含まず、`Symbol`と`Promise`は対象外です。`JSON.parse`は一部の不正なJSONを受け入れるため、厳密な入力検証には使えません。

## ビルド時の変更

- `protectCompatibility`とRollupの`extendscriptCompat()`は、文字列と正規表現のU+200C・U+200D・U+FEFFを標準でエスケープします。識別子やコメントなど、安全に変換できない場所に含まれる場合はエラーにします。出力全体のASCII化は保証しません。
- Rollupの`extendscriptCompat()`は、グローバルの`Number(...)`、直接の`new Number(...)`、参照先を安全に確定できるローカルな別名呼び出しを標準で補正します。変換できない間接参照は既定で警告します。`$.global.Number`、動的な`eval`、外部スクリプトや後から展開するincludeは対象外です。
- `extendscript-compat/number`の`toNumber`を追加しました。明示的に使うことで二進数・八進数文字列や空白の数値変換を補正できます。グローバルの`Number`は置き換えません。

利用方法と対象外の詳細は[ビルド時の互換補正](../build-compatibility.ja.md)と[実行時の互換補正](../../runtime/README.ja.md)を参照してください。Node.js 22以降、Rollup連携にはRollup 4が必要です。

## 検証範囲

After Effects 26.5x89 / ExtendScript 4.5.6の通常版・圧縮版で、[ポリフィル](../evidence/polyfills-ae-26.5.json)、[trimとNumber.parseInt](../evidence/trim-unicode-ae-26.5.json)、[Unicode文字](../evidence/unicode-output-ae-26.5.json)、[数値変換](../evidence/number-ponyfill-ae-26.5.json)と[コンストラクタ・別名](../evidence/number-constructor-alias-ae-26.5.json)を確認しています。他のAdobe製品や旧版では実機未検証です。
