# Changes in 0.4.0

[日本語（正本）](0.4.0.ja.md) | English

In 0.4.0, the Rollup `extendscriptCompat()` plugin automatically validates corrected output as ES3 syntax. Output outside ES3 that previously passed is now rejected, so this changes the accepted input conditions and increments the minor version in the 0.x series. No public APIs or options are added.

## Updates

- Validates every output chunk with Acorn and stops the build with a positioned error when validation fails. Reserved-word properties are checked: `object.for` and `{ default: 1 }` are rejected, while `object["for"]` and `{ "default": 1 }` are accepted.
- Syntax validation remains enabled with `diagnostics: "off"`. Notification settings do not disable it.
- Validation runs after compatibility corrections and BOM insertion. Quoted reserved-word properties, Japanese text, BOMs, and source maps are preserved.
- Acorn is a regular dependency. Consumers do not need to install it directly or call a validation function. Direct calls to existing correction APIs such as `protectCompatibility()` do not include ES3 syntax validation.
- Verification after npm publication waits up to five minutes for registry metadata to propagate. Hash mismatches and network errors are not treated as propagation delays.

## Migration checks

Complete ES3 transpilation, minification, and include expansion before `extendscriptCompat()`. Subsequent minification falls outside its correction and validation guarantees.

When using Terser, set `ie8: true` at the top level. Its defaults may rewrite `object["for"]` to `object.for`, which now fails validation.

```js
terser({ ie8: true });
```

The plugin does not transpile code to ES3. ES2015 and later syntax, TypeScript, ES modules, E4X, unexpanded preprocessor directives, and top-level `return` are not accepted. See [build-time compatibility](../build-compatibility.md).

## Validation scope

Validation covers Ubuntu and Windows with Node.js 22 and 24, public entries and types, normal and minified Rollup output and source maps, rejection of invalid output, and installation from the packed artifact.

The distributed runtime JavaScript is unchanged from 0.3.2. Adobe host tests were not repeated for this release. Syntax validation does not guarantee runtime API availability or behavior in Adobe products; the existing host conditions and limitations in [0.3.1's validation scope](0.3.1.md#validation-scope) still apply.
