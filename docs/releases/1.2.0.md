# Changes in 1.2.0

[日本語（正本）](1.2.0.ja.md) | English

1.2.0 adds a Rollup ponyfill mode that leaves the host application's built-ins unchanged. Supported APIs, including ES5 methods, can use bundle-local implementations while application code keeps ordinary JavaScript syntax. This is a minor-version feature addition under the [v1 compatibility policy](../public-contract.md#changes-after-v1), preserving the existing `/runtime` entry and default configuration.

## Changes

- `extendscriptCompat({ runtime: "ponyfill" })` rewrites supported standard API calls and references to bundle-local implementations. Imports of `extendscript-compat/runtime` in the same bundle become empty, so they do not install polyfills into the host. See [ponyfill mode](../build-compatibility.md#ponyfill-mode) for limitations involving dynamic references and external JSX.
- Transformation now runs on output, covering `Object.keys` and `forEach` in Rollup-generated namespace and re-export code. Function identity across chunks and application bindings are preserved; the internal implementation is excluded from further rewriting.
- When `Object.freeze` is missing, a limited fallback returns its argument unchanged. `/runtime` installs it when missing; ponyfill mode and the final-output correction for direct calls leave the host unchanged. It does not freeze objects or prevent writes, and existing functions are preserved.
- Limited fallbacks for `Object.create`, `Object.defineProperty`, and `Object.getOwnPropertyDescriptor` are available in both `/runtime` and ponyfill mode. Existing functions take precedence. create accepts an object, function, or null as its prototype. When null is specified, it requires a real null prototype or throws TypeError. The defineProperty fallback assigns values, ignores attributes, and rejects getters and setters. Descriptor retrieval is limited to ordinary own data, with approximated writable and configurable flags. See [limited Object support](../../runtime/README.md#limited-object-support).
- Fixed first-run ponyfill behavior that added `String.prototype.this`, and corrected the native reference used for `substr`.

## Installation and migration

Update the dependency to 1.2.0 and rebuild generated JSX. For a new installation that leaves the host unchanged, place this plugin after ES3 syntax transformation, minification, and include expansion, but before JSXBin conversion:

```js
import { extendscriptCompat } from "extendscript-compat/rollup";

export default {
  plugins: [extendscriptCompat({ runtime: "ponyfill" })],
};
```

If the application already imports `/runtime`, this configuration suppresses that import within the same bundle. Omitting the option retains the existing polyfill installation behavior. It does not remove polyfills installed earlier by another script.

Expand includes during an earlier module hook or an earlier renderChunk within the scope that can access the helpers. Late expansion and untransformed supported references added outside an IIFE produce an error. Minifying corrected output again can undo protection.

Rollup external namespaces that require getters fail on AE hosts without getter support. Applications that accept snapshot values may explicitly choose `output.externalLiveBindings: false`. The library does not force that option or `output.freeze: false`.

## Validation scope

The implementation was integrated through [PR #49](https://github.com/YukiWorks432/extendscript-compat/pull/49) to [#53](https://github.com/YukiWorks432/extendscript-compat/pull/53). The final implementation passed 388 regression tests, packaged installation, execution and type checks, and CI on Ubuntu and Windows with Node.js 22 and 24.

On AE 26.5x89 / ExtendScript 4.5.6, four separate processes launched with `-m` started with all three Object APIs absent. Normal and minified ponyfill builds each passed 794 checks without changing host built-ins. Normal and minified polyfill builds each passed 31 checks, including installation and stable function references after reloading. Runtime identifiers and artifact SHA-256 hashes are recorded in the AE evidence section of [PR #53](https://github.com/YukiWorks432/extendscript-compat/pull/53).

This version and distribution-documentation update does not change implementation code. Generated JSX hashes are compared with the existing host evidence; host tests and performance measurements are not repeated. Host acceptance is limited to the Windows AE environment above and does not claim validation on other Adobe applications, older versions, or macOS.
