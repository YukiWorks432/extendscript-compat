# Changes in 0.3.0

English | [日本語（正本）](0.3.0.ja.md)

Version 0.3.0 expands runtime compatibility and adds Unicode and numeric conversion corrections. More transformations now run by default during builds, so check the output and warnings when upgrading from 0.2.0.

## Runtime compatibility

`extendscript-compat/runtime` now includes partial JSON, ES5, and ES6 polyfills. Loading it also affects other scripts sharing the same ExtendScript engine. `trim` handles the whitespace defined by current ECMAScript, and `Number.parseInt` is the corrected `parseInt` function. This is not a complete ES5 or ES6 implementation; `Symbol` and `Promise` are excluded. `JSON.parse` accepts some invalid JSON and must not be used for strict input validation.

## Build changes

- `protectCompatibility` and Rollup's `extendscriptCompat()` escape U+200C, U+200D, and U+FEFF in strings and regular expressions by default. They report an error when these characters occur in identifiers, comments, or other locations that cannot be safely transformed. They do not guarantee ASCII-only output.
- Rollup's `extendscriptCompat()` adds a UTF-8 BOM to output by default. Set `bom: false` to disable it; output without a BOM containing non-ASCII characters produces a warning.
- Rollup's `extendscriptCompat()` corrects global `Number(...)`, direct `new Number(...)`, and local alias calls whose references can be resolved safely by default. Unsupported indirect references produce a warning by default. `$.global.Number`, dynamic `eval`, external scripts, and includes expanded later are outside the scope.
- The new `extendscript-compat/number` entry exports `toNumber` for explicit correction of binary and octal strings and whitespace in numeric conversions. It does not replace the global `Number`.

See [build compatibility](../build-compatibility.md) and [runtime compatibility](../../runtime/README.md) for usage and limitations. Node.js 22 or later and Rollup 4 for Rollup integration are required.

## Validation scope

Normal and minified output has been checked in After Effects 26.5x89 / ExtendScript 4.5.6 for [polyfills](../evidence/polyfills-ae-26.5.json), [trim and Number.parseInt](../evidence/trim-unicode-ae-26.5.json), [Unicode characters](../evidence/unicode-output-ae-26.5.json), [numeric conversion](../evidence/number-ponyfill-ae-26.5.json), and [constructors and aliases](../evidence/number-constructor-alias-ae-26.5.json). BOM behavior was also tested in [After Effects 2025 and 2026](../evidence/bom-ae-2025-2026.json) and [After Effects 2024](https://github.com/YukiWorks432/extendscript-compat/pull/15). Other Adobe products and versions have not been tested on a host.
