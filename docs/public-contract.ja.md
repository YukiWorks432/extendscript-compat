# v1の公開契約

[English](public-contract.md) | 日本語（正本）

この文書は、1.xで互換性を維持する対象として確定した契約です。現在の0.xを1.0.0として公開したことや、未実施の実機検証が完了したことを示すものではありません。個別の挙動は、ここから参照する利用文書と同梱の型宣言を正本とします。

## 公開入口と型

| 入口                             | 保証する役割                                                                                                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `extendscript-compat`            | `protectPrecedence`・`findPrecedenceIssues`・`assertPrecedenceProtected`、`protectCompatibility`・`findCompatibilityIssues`、`protectUnicode`・`findRegExpRisks`と、その戻り値・診断・編集位置の型 |
| `extendscript-compat/rollup`     | `extendscriptCompat(options)`と`CompatibilityOptions`。Numberの自動変換、出力の互換補正、BOM、ES3構文検査                                                                                          |
| `extendscript-compat/runtime`    | 明示的な読み込みによる組み込みAPIの補完・補正と、対応する追加型宣言                                                                                                                                |
| `extendscript-compat/number`     | ホストのNumberを置き換えない`toNumber`                                                                                                                                                             |
| `extendscript-compat/unit-value` | `subtractUnitValues`・`isNull`と`UnitValueLike`                                                                                                                                                    |

`extendscript-compat/package.json`による配布情報の参照も維持します。内部ファイルの配置、依存する解析器のAST・例外オブジェクトの独自フィールド、導入済み印の名前や値は公開契約に含めません。実装依存のファイルを直接読み込まず、上記の入口を使ってください。

## ビルド時の契約

入力は通常のJavaScriptとして生成されたコードです。TypeScriptの変換とES3構文への変換は利用側で行います。E4Xと未展開のプリプロセッサー指示を含む生のJSXは対象外です。解析できない入力は例外にし、無補正の成功として扱いません。

補正は[ビルド時の互換補正](build-compatibility.ja.md)に記載した評価結果、短絡評価、副作用の順序と束縛を保ちます。正規表現の`source`など、表記の変化が観測される箇所は同文書の制限に従います。直接呼ぶ補正APIにはES3構文検査を追加しません。

RollupではTypeScriptなどの変換後にNumberのモジュール内参照を処理し、圧縮・include展開後の出力を互換補正します。ES3構文検査は互換補正とBOM付与の後に常時行い、不適合ならビルドを停止します。`diagnostics: "off"`でも有効です。検査専用の公開APIと無効化設定は設けません。

| 設定                | 既定値   | 契約                                                                                                                 |
| ------------------- | -------- | -------------------------------------------------------------------------------------------------------------------- |
| `diagnostics`       | `"warn"` | EC-03と自動変換できないNumber参照を通知します。`"error"`は停止、`"off"`は通知を省きます                              |
| `regexpDiagnostics` | `"off"`  | EC-18・19の可能性の通知を独立して制御します。自動修正と完全な安全判定は行いません                                    |
| `bom`               | `true`   | 各JavaScriptチャンクの先頭にBOMを一つ付けます。無効化時の非ASCII出力への`MISSING_BOM`警告は`diagnostics`とは独立です |

保証する出力は、このプラグインの`generateBundle`処理を終えた時点のコードです。その後に同じフックでコードを書き換えるプラグインや再圧縮を実行すると、その変更は補正・検査の対象になりません。JSXBin化はこの処理の後に置きます。

有効な先行ソースマップがある場合、外部・inline・hiddenのマップを補正に合わせて更新します。先行処理が失った位置情報の復元は保証しません。

公開診断型のフィールド、`code`・`kind`の意味、位置の基準、警告・停止条件を維持します。直接APIの位置は元入力を基準とし、行は1始まり、列と文字位置はUTF-16のコード単位で0始まりです。RollupのNumber診断はモジュール、互換補正と正規表現診断は補正前の出力、ES3構文エラーは補正後の出力を参照します。説明文の完全一致や、内部解析器固有の例外の形式は保証しません。

## 実行時の契約

`Object.freeze`の未対応時の代替処理は、入力をそのまま返すだけで凍結を保証しません。`/runtime`では不足時に導入し、ponyfillとRollupの最終出力の補正ではホストを変更せず扱います。既存の関数がある場合は維持します。

Rollupの`runtime: "ponyfill"`は、[ビルド時の互換補正](build-compatibility.ja.md#ponyfillモード)で定める標準API参照を、ホストを変更しないバンドル内の実装へ変換します。このモードでは同じバンドルの`/runtime`読み込みを空にし、設定を省略した時の導入契約は維持します。動的参照や外部コードの制限は参照先に従います。

`/runtime`はアプリケーションと依存ライブラリの初期化前に明示的に読み込みます。同じエンジンの他のスクリプトへも影響し、保存済みの古い関数参照は変更しません。通常入口と`/rollup`はランタイムを自動導入せず、`/number`と`/unit-value`も読み込みだけではホストのクラスや関数を置換しません。

同じ版の再読み込みで関数を重ねて包みません。正常と判定した既存の補完対象APIは保持し、既知の不具合を持つ4関数は[実行時の互換補正](../runtime/README.ja.md)の条件で置換します。別ライブラリによる後からの上書きを自動で取り消しません。旧版との読み込み順は、実機検証記録に示す条件までを確認済みとします。

JSONの補完版はJSON文法に従い、不正な入力を`SyntaxError`として拒否します。ES5の`reviver`による子から親への処理、値の置換・削除、入力の一度だけの文字列化を扱います。文法の確認は、利用側のデータ構造・値域の検証を代替しません。新しい規格の`reviver`第3引数などは保証対象に含めません。

APIごとの補完範囲とホスト依存の制約は[実行時API対応表](../runtime/API-COMPATIBILITY.ja.md)に従います。ES5・ES2015以降の全面的な再現、Symbol・Promise、正規表現エンジン全体、UnitValueの通常の演算子の自動補正は保証しません。

Object.create・Object.defineProperty・Object.getOwnPropertyDescriptorの不足時は[Objectの限定補完](../runtime/README.ja.md#objectの限定補完)を適用します。値の代入を優先し、属性制御やgetter・setterを完全に再現しません。ネイティブ関数の保持、実際のnullプロトタイプ、未対応操作のエラーを契約とします。

## 実行環境と出荷確認

ビルド側はNode.js 22以降とRollup 4を対象とします。CIで確認する組み合わせはUbuntu・WindowsとNode.js 22・24です。ホスト側の確認基準はWindowsのAfter Effects 26.5x89 / ExtendScript 4.5.6です。Illustrator・Photoshop・Premiereの確認は、[1.0.0の検証記録](release-1.0.0.ja.md)に記載した版・機能・導入状態に限ります。未検証の機能、古い製品、macOSを対応確認済みとして表示しません。

1.0.0の出荷判断には、通常版・圧縮版を別々の未導入エンジンへ初回導入した結果、再読み込み、旧版共存、利用側の出力・代表操作・ビルド時間と、その後の修正範囲の確認結果を組み合わせて用います。対象コミットと生成物のハッシュを記録し、変更のない範囲の証跡は維持します。版番号・文書だけの更新では実機検証や性能測定を一律に繰り返しません。挙動の変更や新しい不具合が生じた場合に、その影響範囲を追加確認します。個別試験やNodeの模擬環境だけで実機確認を完了扱いにせず、公開契約の確定と実際の出荷記録を区別します。

## 1.x以降の変更

[SemVer](https://semver.org/lang/ja/)に従い、この文書と参照先で保証した契約を基準に版を決めます。

- パッチ更新: 保証した挙動を回復する、後方互換性のある不具合修正。
- マイナー更新: 既存利用を壊さない機能・APIの追加、非推奨化の案内。
- メジャー更新: 保証した入力の拒否、APIの削除、正常な既存利用を壊す既定値の変更など。

公開済みの版は上書きしません。変更が入力条件や対応環境へ影響する場合は、必要な移行を日英の変更案内へ記載します。0.xの公開判断は[npm公開手順](https://github.com/YukiWorks432/extendscript-compat/blob/main/docs/npm-publication.ja.md)に従います。
