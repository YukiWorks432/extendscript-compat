# 1.0.0の変更点と出荷判断

[English](release-1.0.0.md) | 日本語（正本）

1.0.0は、[公開契約](public-contract.ja.md)を1.xの互換性維持の基準として適用する版です。公開入口、入力条件、診断、実行時の副作用とSemVerの方針を確定しています。この文書の追加と版番号の更新では、補正コードを変更していません。npm公開は、準備PRのマージ後に手動で行います。

## 0.4.0からの変更と移行

JSON.parseの補完版は、不正なJSONをSyntaxErrorとして拒否します。reviverによる子から親への処理、置換・削除、入力の一度だけの文字列化も扱います。以前の寛容な解析を前提にした入力は、正しいJSONへ修正してください。

PremiereでObject.keysが文字列の添字を省略する場合にも、Object.entriesとObject.valuesがUTF-16の文字単位を返すよう補正しました。文字列オブジェクトの追加プロパティを保持し、0.4.0との先読み・後読み込みも確認しています。

公開入口とRollup設定の変更はありません。ES3構文検査は引き続きextendscriptCompat()内部で常時実行します。型宣言だけでAPIを利用可能と判断せず、[実行時API対応表](../runtime/API-COMPATIBILITY.ja.md)の補完範囲と制限を確認してください。

実機の版はAE 26.5x89 / ExtendScript 4.5.6、Illustrator 30.8.2 / 4.5.6、Photoshopは#44確認時27.11.0・#45確認時27.9.0 / 4.5.12、Premiere Pro 26.5.2 / 4.5.6です。環境ごとの記録を維持し、古い製品やmacOSへ一般化しません。Premiere全体を公開契約の保証対象へ追加するものではありません。

Premiereの直接実行では、初回の通常版と、その後に同じエンジンの状態を復元した3条件を確認しています。起動時の /C es.processFile 経路ではObject.keysが未定義で、BridgeTalk経路の不完全な既存Object.keysとは初期状態が異なりました。両経路の結果を同一条件として扱いません。

検査後の関数値と確認した文書状態は維持されています。初期の検査器にはES5・ES6キャッシュの復元漏れがあり、修正後に共存・利用側を再確認しました。正規表現の直前一致情報はAPIの復元判定から除外しています。Premiere直接実行の初回にはparseInt・parseFloatの大域プロパティの所有属性差が残りましたが、元の関数値は復元されています。

## 利用側のビルド性能

Windows、Ryzen 7 9800X3D（8コア16スレッド）、Node.js 24.22.1、pnpm 12.6.0。全88本、並列度4、各版1回の準備実行と交互順の5回測定です。依存導入時間は含みません。

| 対象          | 中央値  | 最小〜最大     | 生成物合計       |
| ------------- | ------- | -------------- | ---------------- |
| 公開済み0.4.0 | 46.17秒 | 45.23〜54.34秒 | 10,312,588バイト |
| #44統合後     | 48.18秒 | 47.17〜57.78秒 | 10,358,249バイト |

差は2.01秒（4.36%増）、生成物は45,661バイト（0.44%増）です。#45後の性能を新たに測った値ではありません。実行時の処理時間やJSON.parse単体の性能も未測定です。

個人用側は当時0.3.1と旧圧縮設定だったため、一時コピーの両版へ最上位のTerser設定 ie8: true を追加しました。conditionals: falseは維持し、元の利用側は変更していません。公開テンプレートは既存設定で成功しています。利用側の代表操作は結果表示の待機だけを検査用に差し替えており、ダイアログの描画・クリック検査ではありません。Premiere専用の利用側スクリプトはありません。
